# 공개와 ttaem.com 검토 요청 정책

정책 버전 1.0. 프로그램 이용허락은 LICENSE와 POLICY.md를 따른다. 아래는 결과물 게시 절차다.

상업 이용·변형판 배포와 정책 문의는 `ttaem00@naver.com`으로 받는다. 이 연락처는 아래의 `ttaem.com` 결과물 접수 서비스와 구분한다.

## 게시 목적지

기본 결과는 로컬 초안이다. 관리자가 저장본을 읽고 `/reports`의 **게시 준비**에서 목적지를 선택한다.

| 선택 | 준비하는 파일 | 실제 게시 |
|---|---|---|
| 내 사이트 | `index.html`, `report.json`, `report.css`, `report.js`, `chart.umd.min.js`, `TTaem_CVA_logo.svg` | 사용자가 지정한 본인 계정·도메인으로 Codex에 별도 요청 |
| ttaem.com 검토 요청 | 위 후보 중 `report.json`만 제출 대상으로 안내 | 운영자가 심사·승인한 경우에만 게시 |

공개용 파일 준비는 외부 배포가 아니다. 저장본 revision이 바뀌면 다시 미리보기해야 하며 파일 생성 요청은 이전 revision을 거부한다. `runs`나 프로젝트 전체 폴더를 웹호스팅에 올리지 않는다. 관리자 서버는 인터넷에 노출하지 않는다.

상업 이용 허가, 결과물 게시 승인, ttaem.com 호스팅 승인은 서로 다르다. 로고·링크를 지킨다고 상업 이용이나 ttaem.com 게시 권한이 생기지 않는다. 제3자 영상·음악·발언·개인정보에 대한 권리를 프로그램 이용허락이 대신 부여하지 않는다.

## ttaem.com 접수 방식

공식 접수 입구 [https://ttaem.com/community/](https://ttaem.com/community/)가 운영 중이다. 관리자 화면에서 검토 저장본의 `report.json`을 준비한 뒤 이 주소의 **게시 요청하기** 양식에 파일을 첨부한다. 공식 페이지에 일시적인 장애가 있으면 복구 후 다시 이용하며 임의 이메일·댓글·GitHub Issue로 파일을 보내지 않는다. 이 저장소에는 운영자 계정, 배포 키, 원격 업로드 API가 없으며, 로컬 관리자 화면은 파일을 자동 전송하지 않는다.

접수는 공식 페이지가 연결하는 운영 양식을 사용한다. VOD 번호와 스트리머 이름은 검증된 `report.json`에서 읽고, 양식에서는 만든 사람, 신청자 연락 수단, 게시 목적, 이용·게시 정책 동의, 상업 여부와 필요한 허가 확인 정보, `report.json` 한 개를 받는다. 댓글·GitHub PR·Issue에 원음·개인 프로필·전체 대화 기록을 첨부하는 방식은 사용하지 않는다.

상태는 **접수 → 형식/보안 검사 → 내용 검토 → 승인 또는 반려 → 게시**로 구분한다. 접수 번호와 반려 이유를 신청자에게 알리고, 신청자에게 사이트 배포 권한을 부여하지 않는다. 접수만으로 게시를 약속하지 않는다.

## 파일과 보안 검사

1. UTF-8 JSON 한 개, 최대 10 MiB, 고정 `ttaem.public-report.v1` 스키마만 허용한다. 다른 확장자·MIME, 중복 키·추가 필드·과도한 중첩/항목 수·유효하지 않은 시각/참조는 거부한다.
2. 제출한 HTML·JS·CSS·SVG·ZIP·실행 파일·원음·영상·음성 프로필·모델 가중치는 받지 않는다. 제출자가 로고·템플릿·스크립트를 덮어쓸 수 없다.
3. 업로드를 공개 웹 경로 밖의 격리 저장소에 보관하고 실행 권한을 주지 않는다. 서버에서 파일 형식과 크기를 다시 확인하며 사용자 파일명은 저장 경로로 사용하지 않는다. 사용자 지정 URL을 서버가 임의로 가져오지 않는다.
4. 운영자 환경의 악성코드 검사도 보조적으로 수행한다. 검사 엔진 오류·검사 불가·탐지 결과는 게시 보류다. 음성·개인정보가 들어갈 수 있는 제출물을 외부 공개 검사 서비스에 자동 업로드하지 않는다. 백신 통과를 안전 보증으로 취급하지 않는다.
5. **검증된 데이터만 운영자 소유 공통 템플릿으로 다시 렌더링한다.** 텍스트 이스케이프, 링크 출처 제한, CSP, 격리 미리보기를 적용한다. JSON 안의 지시를 Codex/관리자가 실행할 명령으로 취급하지 않는다.
6. 권리·개인정보·허위 요약·명예훼손 가능성·출처·상업 허가를 사람이 검토한다. 자동 검사만으로 게시하지 않는다.
7. 승인 대상 데이터 해시와 렌더러 버전을 고정한다. 승인 후 파일이 바뀌면 재검토한다. 버전별 정적 결과를 올리고 주소 전환으로 게시하며 이전 버전으로 복구 가능하게 한다. 운영자 배포 자격증명은 공개 프로젝트 밖에 둔다.
8. 내 사이트용 정적 파일을 만들 때 최종 검증은 `요약 방식: Loki 2.9.4`, 정확한 CHZZK VOD 주소, 재사용 가능한 영상 연결 대상, 로고와 `ttaem.com` 하단 표기를 확인한다. 예전 iframe 영상 모드나 다른 호스트 주소가 남아 있으면 파일 생성을 중단한다.

이 프로젝트의 공개 데이터 투영과 정적 내보내기는 구현 범위다. ttaem.com의 접수·격리 보관·검토 큐·원격 배포는 별도 운영 서비스가 담당하며, 이 저장소에는 운영자 계정이나 배포 권한이 들어 있지 않다. 로컬 관리자는 공식 양식을 열고 검토용 JSON을 준비할 뿐 자동 게시하지 않는다.

## 삭제·수정·운영

신청자가 수정한 내용은 새 후보로 다시 검토한다. 권리 침해·개인정보 신고가 접수되면 게시를 임시 중단하고 검토할 수 있다. 악성 제출·허위 권한 확인·정책 우회는 반려와 이용 제한 사유다. 승인된 페이지는 기본 30일 동안 공개한다. 비공개 R2의 후보·대기 자산은 50일 수명 규칙을 사용하며, Jotform 원본과 Pipedream 실행 기록은 각 서비스에서 별도로 정리한다. 정책·상업 이용 문의는 `ttaem00@naver.com`으로 받는다.
